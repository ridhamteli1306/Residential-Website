# Bug Tracker
This file keeps track of all bugs and issues encountered during the development of the Terrazas de Guacuco Residential Website.

## 1. Services Page Navigation Bug
- **Date:** 2026-02-22
- **Issue:** Navigating `Homepage -> Services -> Community Center -> Request Booking` and then pressing the browser's Back button twice to return to the `Services` page caused all amenity cards (except the Community Center card) to become unclickable.
- **Cause:** The "Request Booking" buttons on the individual service pages and homepage were using standard HTML `<a>` tags instead of React Router's `<Link>` components. This caused a full page reload when navigating, breaking the Single Page Application (SPA) state and detaching React event listeners when the browser loaded the previous page from the `bfcache` (Back-Forward Cache).
- **Resolution:** Replaced all `<a href="...">` anchor tags with React Router `<Link to="...">` components across all service pages (`CommunityCenter.jsx`, `Landscaping.jsx`, `ResortPool.jsx`, `SportsFacilities.jsx`) and the `Home.jsx` page. This ensures all navigation is actively handled by React within the DOM, preserving state perfectly when the Back button is used.
- **Status:** Fixed

## 2. Login API Connection Failure
- **Date:** 2026-02-22
- **Issue:** Unable to log in using valid credentials (`manager@terrazas.com` / `managerpassword`) on the frontend `Login.jsx` page. The Axios request to `/api/auth/login` would fail.
- **Cause:** The backend Node.js Express server (`server.js`) was not running in the background. Because the server wasn't active on port 3001, the React frontend could not establish a connection to verify the credentials against the SQLite database. 
- **Resolution:** Started the backend server process (`node server.js` inside the `server` directory) so it listens for incoming API requests on port 3001. 
- **Status:** Fixed

## 3. Frontend Site Unreachable
- **Date:** 2026-02-22
- **Issue:** After refreshing `http://localhost:5173/`, the browser displayed a "site can't be reached" error.
- **Cause:** The Vite React development server process had crashed or been stopped in the background. Without this local development server running, the browser cannot load the React application.
- **Resolution:** Manually restarted the frontend development server by running `npm run dev` inside the `client` directory.
- **Status:** Fixed

## 4. SQLite Database Locking During Seed
- **Date:** 2026-02-22
- **Issue:** Attempted to log in using a newly seeded Watchman account (`security@terrazas.com`), but received an "incorrect email or password" error.
- **Cause:** The `node seed.js` script was executed while the main `server.js` Express server was actively running and holding an open connection cache to the SQLite database. While the script ran successfully, the active backend server did not pick up the newly seeded data.
- **Resolution:** Force-stopped all running Node processes, ran the seed script cleanly on an unlocked database, and then restarted both the backend and frontend servers `Stop-Process -Name node -Force; node seed.js; node server.js`.
- **Status:** Fixed

## 5. Superadmin Dashboard Data Display Bug
- **Date:** 2026-02-23
- **Issue:** The Superadmin Dashboard displayed 0 Total Users and an empty Global User Directory table.
- **Cause:** The frontend code in `SuperadminDashboard.jsx` was incorrectly targeting the API endpoints `/users` and `/users/${userId}`. The backend, however, routes all user management through the `/auth` prefix (e.g., `/auth/users`).
- **Resolution:** Updated the `fetchData` function and `handleDeleteUser` method in `SuperadminDashboard.jsx` to use the correct API paths: `/auth/users` for fetching and `/auth/users/${userId}` for deletion.
- **Status:** Fixed

## 6. Leaflet Map Crashing Vite Development Server
- **Date:** 2026-02-23
- **Issue:** The `VisitorDashboard` caused a fatal frontend crash resulting in a `[plugin:vite:import-analysis] Failed to resolve import` error. The entire website became unreachable.
- **Cause:** The `CommunityMap.jsx` component was using older Node.js `require()` statements to load the default location pin images for the `react-leaflet` map. Vite is an ES Module bundler and strictly does not support CommonJS `require()` syntax in the browser frontend code, causing the build process to fail immediately.
- **Resolution:** Refactored the marker image loading in `CommunityMap.jsx` to use standard ES6 `import` paths for `marker-icon.png`, `marker-icon-2x.png`, and `marker-shadow.png`.
- **Status:** Fixed

## 7. Javascript Date UTC Timezone Shift
- **Date:** 2026-02-24
- **Issue:** On the Superadmin Visitor Directory, applying a "From Date" or "To Date" filter (e.g., filtering for Feb 1st) would consistently match and display records from the day prior (Jan 31st).
- **Cause:** Selecting a date from an HTML `<input type="date">` returns a string formatted as `YYYY-MM-DD`. Passing this string directly into `new Date('YYYY-MM-DD')` causes Javascript to default to parsing it as midnight UTC (`00:00:00Z`). When compared against the user's local timezone (e.g., UTC-6), this mathematically shifted the comparison boundary backward into the previous evening (6:00 PM the day prior).
- **Resolution:** Modified the filter logic in `SuperadminDashboard.jsx` to manually split the date string (`.split('-')`) and construct a new local Javascript date object (`new Date(year, month - 1, day)`) to force the boundary calculation to happen entirely within the local machine's native timezone.
- **Status:** Fixed
